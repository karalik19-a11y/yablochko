### 3.3 Следствия для архитектуры и плана (важно)

1. **Rust/Axum/Tauri нельзя компилировать в песочнице.** Решение: контрактная
   разработка (ADR-0002) + сборка Rust-артефактов в **GitHub Actions** (там полный
   интернет и тулчейн). Rust-код появляется в репо по мере готовности контрактов
   и собирается/тестируется в CI.
2. **PostgreSQL / ClickHouse / OpenSearch / Valkey / S3 нельзя поднять локально**
   (нет Docker, apt заблокирован). Решение: **два профиля хранения** (ADR-0001) —
   dev/desktop-профиль на embedded-движках (SQLite через встроенный `node:sqlite`,
   DuckDB через npm-биндинги, MiniSearch, in-memory cache), server-профиль — целевой
   стек из мастер-промпта. Логическая схема данных едина.
3. **Реальные источники данных недоступны из песочницы.** Решение: ingestion-коннекторы
   исполняются (а) локально у владельца данных, (б) в GitHub Actions по расписанию,
   (в) на server-профиле партии. Для разработки UI/аналитики — **синтетические
   seed-данные с обязательной пометкой `SYNTHETIC`** (ADR-0005), запрещено выдавать
   их за реальные.
4. **Карта — офлайн.** Границы РФ (TopoJSON/GeoJSON, упрощённые) поставляются в
   комплекте `datasets/geo/`; MapLibre работает на локальных источниках без внешних
   тайл-серверов (ADR-0003).
5. **Live preview в песочнице** — браузерный (Vite dev server + Node API, bind 0.0.0.0).
   Полноценный desktop-опыт проверяется на этапах 15+ через CI-сборку `.exe`.

### 3.4 Канал поставки зависимостей

Единственный доступный канал — npm. Проверена доступность ключевых пакетов
(актуальные версии на дату аудита): `react@19`, `typescript@7`, `vite@8`,
`echarts@6`, `maplibre-gl@6`, `duckdb@1.4` (npm-биндинги с прекомпилированным

### 4.3 Непреложные ограничения (hard requirements, не подлежат оптимизации)

- Нейтральная аналитика: никакой подгонки данных под партийную позицию; hidden results
  запрещены; корреляция ≠ причинность (маркировка категорий знания обязательна).
- **Запрещено** (навсегда, во всех модулях): профилирование частных лиц по политическим
  взглядам; списки «сторонники/противники»; вероятности голосования конкретного
  человека; персонализированные политические сообщения. Объект анализа — **территории
  и агрегаты**, публичные персоны/организации — только по публичным фактам с evidence.
- Каждый вывод: provenance-цепочка до исходного документа (Evidence Graph).
- Категории утверждений строго разделяются: `OFFICIAL RESULT / PARTY STATEMENT /
  INDEPENDENT ANALYSIS / MODEL INFERENCE` — UI обязан визуально различать.
- Внешние документы/страницы **никогда** не могут изменять system instructions AI.

### 4.4 Риски и пробелы требований

| Риск | Влияние | Митигация |
|---|---|---|

## 5. Исходный Party Context — статус достоверности

Мастер-промпт задаёт INITIAL CONTEXT. По правилам самого проекта эти сведения —
**не константы**, а записи Party Position Registry с обязательной верификацией по
официальным источникам. Поскольку песочница не имеет доступа к `yabloko.ru`, все
записи ниже импортируются на этапе 2 со статусом **`UNVERIFIED`** до первого
успешного `VERIFY` из официального источника (CI или локальный запуск коннектора).

| Коммуникация 2026 | «За мир и свободу!», «За жизнь без страха!» | UNVERIFIED |
| Ключевые положения 2026 | прекращение огня, дипломатия, мир, предотвращение ядерной войны, Россия без страха, против репрессий, сохранение жизни, достоинство, права человека, демократическая Россия | UNVERIFIED (позиции вносятся в Registry с date_from/source) |

## 6. Принятые решения (полный текст — docs/ARCHITECTURE.md, раздел ADR)

| ADR | Решение | Причина |
|---|---|---|
| 0001 | Два профиля хранения: Desktop/Dev (embedded) и Server (PostgreSQL/ClickHouse/OpenSearch/Valkey/S3) | среда песочницы + требование офлайн-desktop |
| 0002 | API-contract-first: единый типизированный контракт, адаптеры Node-dev и Tauri-IPC (+Axum в server-профиле) | разработка без Rust-компилятора; одинаковые тесты на всех профилях |
| 0003 | Офлайн-карты: границы в комплекте, MapLibre без внешних тайлов | сеть песочницы; надёжность desktop |
| 0004 | TypeScript-first разработка; Rust-ядро собирается в GitHub Actions | crates.io/rustup заблокированы |
| 0005 | Синтетические seed-данные с жёсткой пометкой SYNTHETIC/DEMO | нет доступа к реальным источникам; запрет имитации реальных данных |
| 0006 | Транзакционные данные: SQLite (`node:sqlite` dev / `rusqlite` desktop); аналитика: DuckDB (dev/desktop) → ClickHouse (server) | embedded-совместимость, columnar для сотен млн строк |
| 0007 | Дистрибуция/обновления: Tauri 2 + GitHub Releases + подпись + rollback | требование этапа 16 |
