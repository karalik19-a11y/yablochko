# ADR-0009. Desktop-профиль: api_cache + живые порты вместо DuckDB-ядра

Дата: 2026-09-24 (Этап 15). Статус: принято.

## Контекст

ARCHITECTURE §3 предполагает в desktop-ядре (core-rs) rusqlite + DuckDB
(аналитика). Локально Rust-тулчейн недоступен (ADR-0002): компиляция только в
CI, каждая итерация — коммит+прогон. Логика API (35+ эндпоинтов, сиды,
медиа/выборы/OSINT/матрица) уже реализована и протестирована в TypeScript
(services/dev-api, packages/data-access). Порт всей логики в Rust означал бы
сотни строк некомпилируемого локально кода с высоким риском расхождения
контрактов.

## Решение

Desktop-профиль = **кэшированная аналитика + живые точечные обработчики**:

1. **api_cache** — на этапе сборки (CI, Node доступен) scripts/
   build-desktop-resources.ts создаёт БД (полный сид через миграции) и
   пре-рендерит 655 ответов GET-эндпоинтов через НАСТОЯЩЕЕ приложение
   (fastify `inject`) в таблицу api_cache. Нулевое дублирование логики:
   Rust отдаёт готовые конверты.
2. **Живое в Rust** — только то, что параметризовано произвольно и/или
   детерминированно простое: decision/compute (точный порт Монте-Карло,
   golden-тесты сверяются со значениями TS), geo/documents/osint search,
   metrics/compare, metrics/trust, analyst/verify, acknowledge. FAQ
   AI-аналитика — 7 канонических запросов через полноценный askAnalyst при
   сборке, точное совпадение вопроса; вне набора — честный fallback-конверт.
3. **DuckDB в ядре отложен**: аналитическая нагрузка desktop-профиля
   (серии, сравнения, карты) покрывается SQLite-кэшем; columnar-движок
   возвращается в ядро вместе с серверным профилем (Axum, Этап 16+/18),
   когда появится реальный импорт объёмов.

## Последствия

- Установщик без Node/Python/Docker; ядро ~изначально read-only (данные
  SYNTHETIC, запись — только acknowledged_at алертов).
- Обновление данных = пересборка ресурсов (до Этапа 16 — автообновления).
- Rust-поверхность мала и покрыта тестами (`cargo test` в CI), риски
  некомпилируемого кода сведены к минимуму.
- Контракт /api/v1 идентичен dev-профилю: SPA работает в обоих профилях
  без ветвлений (fetch-шимбл только перехватывает /api в Tauri).
