# Географические данные (datasets/geo)

## Статус

| Слой | Статус | Источник |
|---|---|---|
| Страна + ФО + субъекты (89) | заполнено (справочник, UNVERIFIED до импорта кодов) | `rf.json`; список по официальной классификации РФ; ISO 3166-2:RU где присвоен |
| Муниципалитеты/города/районы | **pilot_partial** (СПб, Псковская обл.) | `rf.json → municipal_pilot` |
| Границы (TopoJSON/GeoJSON) | **схематическая картограмма** (`grid`-координаты) | генерируется из `rf.json`; реальные границы — при ingestion (CI/локально), см. ниже |

## Картограмма

Слои карты на Этапе 4 используют схематическую tile-картограмму (grid cartogram) —
профессиональный стандарт визуализации территориальной статистики. Методология слоя
обязана помечать: «схематическое представление, не географические границы».

## Замена на реальные границы

Пайплайн ingestion (Этап 3+) поддерживает загрузку файлов. Для замены картограммы:

1. Получить официальные границы (например, из открытых данных Росреестра / OSM —
   с соблюдением лицензии ODbL и указанием атрибуции).
2. Упростить (topojson-simplify), цель — субъекты ≤ 2 МБ суммарно.
3. Положить в `datasets/geo/boundaries_subjects.json` (FeatureCollection,
   свойство `geo_id` в features должно совпадать со stable ID).
4. Эндпоинт `/api/v1/geo/map` отдаст реальные границы вместо картограммы
   (детект наличия файла — в репозитории гео).

## Stable IDs (ADR-0008)

`geo_id = ru:{level}:{код}`. Переименование территории не меняет geo_id;
слияние — новый geo_id + запись в `geo_merges`.
